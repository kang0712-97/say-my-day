## 1. 개인정보 (T11, T12)
**현황(확인함):** 서버 로그는 시작 메시지만 찍고 일기 내용은 기록하지 않는다(`console.log` 3곳). 일기는 브라우저에만 저장. 번역 때 일기 문장이 AI 제공사로, 음성 생성 때 번역문이 음성 서비스(edge-tts)로 전송된다. 설정에 한 단락 안내만 있다.

**T11 (축소) 데이터 흐름 확인 — 내부 기록용**
1. 흐름표 작성(항목 / 어디로 / 목적 / 보관)을 이 파일 아래에 적는다. 처리방침 페이지는 만들지 않는다.
2. 기술 확인 2가지만: ⓐ Render 요청 로그에 본문이 남는지 ⓑ edge-tts로 나가는 정보가 문장 텍스트뿐인지. (AI 제공사 보관 정책 확인은 법률 쪽이라 보류.)
- **보류한 것:** 처리방침 페이지, 이용 연령, 면책 문구, 문의처 — 나중에 필요할 때 이 카드를 되살린다.

**T12 (축소) 내 데이터 모두 지우기**
1. 설정에 **"내 데이터 모두 지우기"**: 확인 한 번 → 일기·단어·문장·표현 사전·글자 풀이 캐시·설정 삭제 → 인트로로 복귀. 지우기 전에 "내보내기 먼저" 버튼 제공(T14의 공유 내보내기와 연결).
2. 시험: 지우기 후 저장소 키 0개, 내보내기 → 지우기 → 가져오기로 복구 가능(분리 서버로만).
- **보류한 것:** 첫 번역 전 동의 모달(법률 성격).

## 2. 음성 (T13)
**현황(확인함):** 향상된 음성은 비공식 edge-tts, 브라우저 내장 음성(`speechSynthesis`)이 이미 있고, 단어 경계 시간이 없으면 재생 위치 비율로 글자 색을 근사하는 폴백이 코드에 있다.

**방침:** edge-tts는 "없어져도 앱이 멀쩡한 선택 기능"으로 낮춘다. 기본 경로는 기기 음성.
1. 서버에 `EDGE_TTS_ENABLED` 스위치(환경변수 하나로 끄기). 꺼지면 `/api/langs`가 음성 없음으로 응답하고 화면이 자동으로 기기 음성만 보여 준다.
2. 설정 문구: "향상된 음성은 외부 서비스를 사용하며 예고 없이 중단될 수 있어요." (기능 안내 목적, 동의 절차는 아님)
3. **장애 시험(필수):** edge-tts 없이 서버 기동 → 듣기·따라 읽기·퀴즈 듣기·통독이 오류 없이 기기 음성으로 동작하는지, 오류 토스트가 한 번만 뜨는지. 도중 실패(음성 요청 5xx)도 같은 폴백.
4. 기기 음성 현황표(실기기): 안드로이드 크롬·아이폰 사파리에서 ja-JP·zh-CN 음성 유무와 품질을 사용자가 확인해 표로 남긴다. 음성이 없는 기기의 안내 문구는 이미 있음 → 문구에 "기기 설정에서 음성 데이터 설치" 방법 한 줄 추가.
5. 무료로 쓸 수 있는 공식 대안(예: 클라우드 사업자 무료 구간)은 `(확인 필요)`: 한도·가입 조건(카드 등록 요구 여부)을 조사만 하고 도입은 결정 사항으로 남긴다.
- 완료 기준: 서버에서 향상된 음성을 끈 상태로 모든 듣기 화면이 오류 없이 동작.
- 결정 필요: 공개 확대 시점에도 edge-tts를 켜 둘지(약관 위험을 감수하는 결정).

## 3. 데이터 보존 (T14)
**현황:** 일기 300편·단어·문장이 브라우저 저장소에만 있고, 내보내기/가져오기(합치기·바꾸기)는 이미 있다. 백업을 안 하면 브라우저 데이터 삭제·기기 변경 때 전부 사라진다.
1. **백업 알림:** 마지막 내보내기 시각 `last-export`를 저장, "마지막 백업 후 일기 N편 / D일 경과"가 기준(예: 5편 또는 14일)을 넘으면 일기장 상단에 조용한 배너 + [백업하기]. 처음 쓰는 사람은 제외.
2. **한 번에 내보내기:** 파일 이름에 날짜(`say-my-day-2026-10-29.json`), 휴대폰에서는 `navigator.share({files})`로 메신저·드라이브에 바로 보내기(지원 안 되면 기존 다운로드). `(확인 필요: 대상 폰에서 파일 공유 지원 여부)`.
3. **저장소 영구 요청:** `navigator.storage.persist()`를 첫 저장 후 호출(허용 여부는 브라우저 판단, 결과는 설정에 "보호됨/아님"으로 표시). 사용량 `storage.estimate()`가 80% 넘으면 안내.
4. **스키마 버전:** 저장 데이터와 내보내기 파일에 `schema: 1` 추가, 가져올 때 낮은 버전은 변환 함수를 거친다(미래 변경 대비). 지금 파일은 버전 없음 = 0으로 취급.
5. 시험(자동): 일기·단어·문장을 채움 → 내보내기 → 저장소 비움 → 가져오기(바꾸기) → 개수·내용 동일. 300편 초과 시 오래된 것 삭제 동작, 저장 가득 참 토스트, 합치기 중복 제거.
- 완료 기준: 왕복 시험 통과, 배너가 조건에서만 나타남.
- 이번 범위 밖(기록만): 계정·기기 간 동기화(M5)는 서버 저장·인증이 필요해 개인정보 부담이 커서 뒤로 미룬다.

## 4. 서버 안정·모니터링 (T15)
**현황:** Render 무료 플랜(무접속 시 잠듦, 첫 요청 30초~1분), 횟수 제한·캐시·음성 파일이 메모리/임시 폴더라 재시작하면 사라진다. `/healthz` 있음.
1. **잠들기 완화(택1 또는 병행):**
   ⓐ 화면이 열리는 즉시 `/healthz`를 한 번 호출해 서버를 깨우고, 아직 응답이 없으면 번역 버튼 근처에 "서버를 깨우는 중이에요(최대 1분)" 표시.
   ⓑ 외부 무료 가동 감시 서비스로 5분마다 `/healthz` 호출 `(확인 필요: 무료 플랜의 월 가동 시간 한도 안에 드는지)`. 한도를 넘으면 ⓐ만 쓴다.
2. **구조화 로그(일기 내용 절대 제외):** 요청마다 한 줄 JSON — 시각, 경로, 조합(src>tgt), 글자 수, 소요 ms, 결과(ok / 오류 코드), 제한 걸림 여부, 모델 사용 토큰 수. 오류 객체에 일기 원문이 섞이지 않게 에러 메시지를 걸러 기록. Render 로그 화면에서 검색.
3. **비용 상한(코드 밖):** AI 제공사 콘솔에서 월 지출 한도와 알림 이메일 설정(사용자가 직접). 코드 쪽은 기존 하루 총량 `LIMIT_PER_DAY`를 환경변수로 쉽게 조절, 총량 소진 시 친절한 문구(있음).
4. **장애 알림:** 가동 감시 서비스의 이메일 알림(ⓑ를 쓰는 경우) 또는 Render 기본 알림. 번역 오류율이 오르면 로그에서 확인하는 절차를 `README`에 한 장으로.
5. **남용 방지 점검:** 본문 크기·글자 수 제한(있음), 조합 검증(있음), `Content-Type` 검증(있음). 추가: `Origin` 헤더가 우리 도메인이 아니면 `/api/translate` 거절(브라우저 남용 완화, 서버 간 호출은 못 막음 → 한계를 문서화).
6. 한계 기록: 횟수 제한이 메모리라 재시작 시 초기화됨. 유료 플랜·디스크 도입 시 재검토.
- 시험: 서버 재시작 직후 첫 화면 → 안내 문구 표시 확인(느린 응답을 가짜로 만들어 시뮬), 로그에 일기 문자열이 없는지 `grep`으로 확인(시험용 일기에 고유 문자열 넣고 로그 검색), Origin 불일치 거절.

## 5. 품질·접근성·자동 시험 (T16~T18)
**현황:** 병음·읽기·문장 나누기·문구 키 검사 스크립트와 `browser_check.js`가 있으나 한 번에 돌리는 명령이 없고, 화면 시험은 이번 대화의 임시 스크립트에만 있다.

**T16 `npm test` + 화면 스모크**
1. `package.json`에 `test` 스크립트: 기존 순수 검사(pinyin, pinyin_context, split, i18n_keys, 일본어 정답 25문장 중 서버 불필요한 것) 순차 실행, 하나라도 실패하면 종료 코드 1.
2. 오늘 쓴 임시 스크립트를 `tests/smoke/`로 정리. 분리 서버를 스스로 띄우고 끄는 러너 하나. 시나리오(고정 샘플 JSON 사용, API 호출 없음): ko>zh 결과 · ko>ja 결과 · zh>ja 결과 · 단어 미니 카드/페이지 · 퀴즈 전 종류 · 통독 · 보관함·설정.
3. 각 시나리오 검사 항목: ⓐ 한국어/중국어 화면에서 **다른 언어 문구 누출 0**(원문 데이터 제외) ⓑ `{자리표}`·undefined·NaN 0 ⓒ **360px 폭 가로 넘침 0**(오늘의 iframe 방식) ⓓ 콘솔 오류 0.
- 완료 기준: `npm test` 한 줄로 통과/실패가 나오고, 일부러 문구를 하나 깨뜨리면 실패한다(시험의 시험).

**T17 번역 품질 정답 세트**
1. 조합별 20문장(난이도·문장부호·숫자·고유명사·긴 문장 혼합). 확인 항목: JSON 형식 유효, 문장 수 일치, 읽기(병음·후리가나) 정답 일치율, 금지어(해명 멘트 등) 없음.
2. 실제 API를 호출하므로 `npm run quality`로 따로 두고 수동 실행, 호출 수·대략 비용을 출력. 결과는 날짜별로 파일 저장해 모델·프롬프트를 바꿀 때 전후 비교.
3. **문구 검수표:** `ZH` 사전을 `원문 | 중국어 | 쓰인 곳 | 검수 메모` CSV로 내보내는 스크립트. 중국인 친구에게 보낼 파일. 일본어 정답 문장은 원어민 검수를 받는다.

**T18 접근성 + 기기**
1. 자동: 이름 없는 버튼·링크·입력 검사(`aria-label`/텍스트 없음), 이미지 대체 텍스트, 포커스 순서 이탈, `lang` 속성(일본어·중국어 조각에 올바른 `lang`). 색 대비는 `contrast-check` 스킬로 라이트·다크 두 테마 모두 표로.
2. 반자동: 글자 크기 200%·확대 상태에서 가로 넘침, 스크린 리더 읽는 순서(한자 위 병음 이중 줄이 어색한지) 샘플 3화면.
3. **기기 매트릭스(사용자 실기기 필요):** 폭 320 / 360 / 390 / 430, 안드로이드 크롬, 아이폰 사파리(지인 폰), 다크 모드, 가로 방향. 각 화면(인트로·쓰기·결과·퀴즈·설정)에 ○/× 표.
- 완료 기준: 자동 검사 0건, 기기 표의 × 항목이 이슈로 정리됨.

**확인 결과**
- ⓐ 서버 코드는 요청 본문·일기를 로그로 남기지 않는다(`console.log`는 시작 메시지 3곳뿐, 요청 로그 미들웨어 없음). **Render 대시보드의 요청 로그에 본문이 보이는지는 확인하지 못했다**(GET/POST 본문은 보통 기록되지 않으나 사용자가 로그 화면에서 확인 필요).
- ⓑ edge-tts 작업 프로세스가 받는 항목은 `text`(문장 텍스트), `voice`, `rate`, `out`(서버 내 파일 경로)이다. 사용자 식별 정보(IP 등)는 넘기지 않는다. 마이크로소프트 쪽 처리는 확인하지 않았다.
- 파생 사항: 에러 메시지에 모델 응답 본문이 섞이면 로그에 일기 일부가 남을 수 있으므로, T15에서 로그를 만들 때 에러 문구를 걸러 쓴다.
