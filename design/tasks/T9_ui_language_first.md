# T9 인터페이스 언어 = 입력 언어 (틀 만들기 + 언어 먼저 고르기)
상태: 대기 · 결과: (끝나면 기록)

## 왜
앱의 목적(사용자 정리, 2026-10-28): 입력 언어가 중국어면 **중국인이 출력 언어(일본어)를 배우려는 것**, 입력 언어가 한국어면 한국인이 출력 언어를 배우려는 것. 그러므로 **화면 전체(설명·버튼·안내·인트로·오류 메시지)가 입력 언어**여야 한다. README 결정 6("화면 문구는 한국어 고정")은 이 카드로 **폐기**한다(CLAUDE.md·README 결정 갱신 필요).
그리고 처음 화면에서 **언어(입력→학습)를 먼저 고르게** 하고, 그 이후의 인트로·설명이 고른 언어로 나오게 한다.

## 먼저 사용자에게 물을 것
1. 언어 고르기 첫 화면 자체는 어떤 언어로? 제안: 두 언어를 나란히(한국어 / 中文) 표시한 "언어 고르기" 한 장.
2. 이후 입력 언어가 영어(en)·일본어가 될 때를 지금 설계에 포함할지(기본: 문구 사전 구조만 열어 두고 ko·zh만 채움).

## 할 일 (예상) — 틀만, 문구 번역은 T10
1. 화면 문구 사전: `const T = { ko: {...}, zh: {...} }`와 `t(key, vars)`. 화면의 한글 약 430줄을 키로 뽑는 작업은 T10에서 하고, 여기서는 사전 틀, `data-t` 속성 적용 함수(`applyLangUI`에 합침), 저장 언어(`lang-src`)에 따른 `<html lang>` 설정, 조사 처리 문제(한국어 "은/는" 등 언어별 문장 조립 금지 → 문장 통째로 키로)를 만든다.
2. 인트로 순서 변경: 1장 언어 고르기(입력 언어 → 학습 언어) → 이후 슬라이드가 고른 언어로 표시. 지금은 3번째 장에 있다(`lpOpen`·`introShow(2)`).
3. 서버: 오류·제한 메시지(`checkTranslateLimit`, `checkSourceLang`, 429/400 문구)를 `srcLang`에 맞는 언어로. 공개 문구는 `code`를 같이 보내 화면이 사전에서 고르는 방식이 깔끔하다.
4. 시험: 문구 사전의 ko·zh 키 개수 일치 검사 스크립트(`tests/i18n_keys_check.js`).
