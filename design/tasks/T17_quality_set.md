# T17 번역 품질 정답 세트 + 중국어 문구 검수표
상태: 일부 완료(검수표 완료, 품질 세트 기준 실행 남음)
근거: `hardening-plan.md §5 T17` (읽고 시작)

## 할 일
조합별 20문장 정답 세트와 `npm run quality`(실제 API, 수동), 결과 날짜별 저장. `ZH` 사전을 CSV(원문|중국어|쓰인 곳|메모)로 내보내는 스크립트.

## 완료 기준
- 세트 실행 결과 기록, 검수표 CSV 생성.

## 결과
**일부 완료.** ① 문구 검수표 `design/zh-review.csv` 생성(ZH 304개 + T 32개, 열: 구분·원문·중국어·쓰인 곳·검수 메모, 스크립트 `tests/quality/export_zh.js`). ② 정답 세트 `tests/quality/sets.js`(조합별 20문장, 숫자·고유명사·쉼표·의문·감탄 포함)와 실행기 `npm run quality`(`tests/quality/run.js`, 실제 API 3회+일본어 읽기 확인 호출, 토큰 수 출력, `tests/quality/results/날짜.json` 저장) 작성. ③ 첫 실행(2026-10-29)에서 세 조합 모두 번역이 돌아옴: ko>zh 결과 문장 22(입력 20, 긴 문장 2개는 앱이 쉼표에서 나눔), ko>ja 22, zh>ja 21. 일본어 한자 단어 82·88개 중 읽기 없음 0, 확인 표시 2·1개. 토큰은 번역 3회 합계 입력 약 8.7천 / 출력 약 1.8만. ④ **미완:** 그 실행기는 결과를 입력 순서대로 짝지어 채점해서, 쉼표로 나뉜 문장 뒤가 전부 어긋난 "문제 93건"이 나왔다(채점 오류이지 번역 오류가 아님). 이후 채점을 원문 일치로 묶도록 고쳤지만, 고친 뒤 세 번 다시 돌렸을 때 AI 호출이 시간 초과·`fetch failed`로 전부 실패해 **고친 채점의 통과/실패 결과는 아직 없다**(실패한 결과 파일은 지움). 첫 결과를 느슨하게(문장 전체에서 찾기) 다시 보면 앞 18문장의 핵심 요소(숫자·고유명사·낱말)는 모두 들어 있었으나 저장본이 앞 20문장만 남겨 19·20번은 판단 못 함. 번역 품질 일치율은 정답과 비교한 것이 아니라 핵심 요소 유무만 본다. **남은 일:** 네트워크가 안정될 때 `npm run quality` 한 번 더(약 3~5분, 토큰 위 수준) 돌려 기준 결과 파일을 남기기. 일본어 정답 문장 원어민 검수, 검수표 회수는 사용자 몫.
