# T5 일본어 글자별 풀이 (한자 의미를 글자마다)
상태: 완료(사용자 확인 2026-10-27) · 결과: 友達·食べ物·勉強·今日·市場 모두 한자 글자 수와 같은 항목, 今日·大人는 통째 읽기(whole)로 표시. 글자 수 불일치는 버림(캐시 안 함). 중국어 학校 회귀 없음, 캐시 키 `ja:단어`로 분리. 호출 수는 중국어와 같음(한 번에 12단어, 공개 모드 시간당 60회, 같은 제한·동시 제한 공유). 한계: 단어만 보고 읽기를 정해 市場처럼 읽기가 갈리는 말은 문맥과 다를 수 있음(프롬프트에 "전체 읽기 먼저 정하기" 규칙으로 市場=しじょう 확인), 日本人의 に 같은 쪼개기는 AI 판단.

## 왜
사용자 요청: 단어 자세히 보기에서 한자 의미가 글자마다 개별로 나와야 한다. 지금 글자별 풀이(`/api/chars`)는 중국어 전용이라 일본어에서는 숨겨 둠(`hasHan`).

## 할 일
1. 서버: `/api/chars`에 `lang` 받기. 일본어용 시스템 프롬프트(`CHARS_SYSTEM_JA`): 단어의 한자 글자마다 `{ch, reading(이 단어에서의 읽기, 음독/훈독 표시), hun(한국 한자 훈음, 확실하지 않으면 빈 문자열), meaning(이 단어 안에서의 뜻 12자 안팎)}`와 `how`(글자 뜻이 합쳐지는 과정 한 줄). 가나 부분(활용 어미 등)은 풀이에서 빼고 한자 글자만. 熟字訓(今日·大人 등 글자별로 나눌 수 없는 말)은 "이 단어는 통째로 읽어요"로 솔직히 표시. 서버 캐시 키와 `charsHits` 제한에 언어 포함.
2. 화면: `hasHan`을 일본어 한자도 허용(`LANG.tgt` 기준), `charCache` 키를 `ja:단어`처럼 언어 접두어로(중국어 기존 캐시는 그대로 읽히게). `charsHtml`이 일본어 항목(읽기 표시, 한자가 없는 글자 건너뛰기)을 그린다. 번역 직후 핵심 단어 미리 받기(`prefetchChars`)도 일본어에서 동작.
3. 한국 한자 훈음은 AI가 지어낼 수 있으므로 "확실하지 않으면 비움" 규칙 유지. 일본 신자체(例: 国·学·験)가 한국 한자와 다르면 한국 한자 쪽 훈음을 쓰되 모르면 비움.

## 완료 기준
- 샘플 단어 友達·食べ物·勉強·今日·市場에서 글자별 항목이 정확한 개수로 나오고(한자 글자 수와 같음) 今日는 통째 읽기로 표시. 서버 응답 형식 검사(글자 수 불일치 시 버림).
- 중국어 글자별 풀이 회귀 없음, 같은 단어(学校)가 중국어·일본어 캐시에서 섞이지 않음.
- 비용: 한 번에 풀이하는 단어 수·호출 제한이 중국어와 같은 수준인지 기록.
- 사용자 확인 요청: 일본어 풀이 내용(한국 한자 훈음이 맞는지, 풀이가 자연스러운지).
