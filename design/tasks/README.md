# 작업 카드 방식 (기능 하나 = 카드 한 장 = 새 대화 하나)

목적: 대화가 길어지면 앞 내용을 놓치고 토큰이 늘어난다. 기능마다 새 대화로 시작하고, 이어 가는 데 필요한 모든 것을 **카드 파일**에 적어 둔다.

## 새 대화 시작 문장 (사용자가 그대로 붙여 넣는다)
```
01.program/say-my-day 폴더의 CLAUDE.md와 design/tasks/README.md를 읽고, 현황판에서 "대기"인 첫 카드를 진행해줘.
```

> **T29~T34는 사용 피드백 반영 카드다(2026-10-30 승인). T29~T31 후 한 번 배포를 권함.** 배포 승인은 아직 안 받음.

> **T19~T28은 그림일기 개편 카드다.** 시작 전에 `design/redesign-plan.md`와 `/say-my-day-design` 스킬 절차를 따른다. 순서대로 진행한다(앞 카드가 뒤 카드의 바탕).

## 한 카드의 진행 규칙 (Claude가 지킨다)
1. **읽는 것은 CLAUDE.md → 이 README → 해당 카드 한 장**뿐. 코드는 카드에 적힌 `grep` 단어로만 찾아 읽는다(통째로 읽지 않는다). 카드에 없는 큰 결정이 필요하면 사용자에게 먼저 묻는다.
2. 시작하면 카드 상태를 `진행 중`으로 바꾸고, `backup/index_<이름>_vN.html`(현재 v44 다음 번호)으로 이전 버전을 보관한다.
3. 카드의 **완료 기준**을 하나씩 시험으로 확인한다. 시험은 **분리 서버**로만 한다(데이터 안전 규칙). 사람이 귀·눈·휴대폰으로 확인할 항목은 "확인하지 못했다"고 적고 사용자에게 요청한다.
4. 끝나면: ① 카드에 `결과` 칸(한 줄 요약+수치) 기록 ② 현황판 상태를 `완료(미확인: …)`로 ③ `README.md` 개편 이력 한 줄 ④ 로컬 커밋 ⑤ **사용자에게 "이 카드 끝. /clear 후 시작 문장을 다시 붙여 넣으세요"라고 알린다.** 한 대화에서 다음 카드로 넘어가지 않는다.
5. 카드가 한 대화에 너무 크다고 판단되면(코드 수정 3곳 이상 + 시험이 길어짐) 중간에 카드를 둘로 쪼개 현황판에 적고 첫 번째만 끝낸다.
6. 결정 사항: **유료 음성·유료 서비스는 쓰지 않는다**(사용자 결정, 2026-10-27). ~~앱 화면 언어는 한국어로 둔다.~~ → **2026-10-28 폐기(T9)**: 화면 언어는 입력 언어를 따른다(입력=중국어면 중국인이 일본어를 배우는 앱).

## 이미 알고 있는 사실 (카드마다 다시 조사하지 않는다)
- 일본어 번역·읽기는 서버가 `ja` 키를 화면용 `zh` 키로 바꿔 보낸다(`app/ja_reading.js`). 단어에는 `reading`(히라가나 AI)·`check`/`kuro`(분석 도구와 다를 때)가 있다.
- 화면은 "한 글자 = 한 칸(`.c`)" 구조이고 따라 읽기(`karLineFor`, `karBegin`)·형광펜·문장 속 단어 위치(`ctx_i`)가 이 구조에 기대고 있다. 일본어 읽기 토큰은 글자 수와 같게 만든다(`jaCharTokens`, `jaSplit`, `wordTokens`).
- 소리: 서버 `makeSpeech`+`tts_worker.py`(edge-tts), 단어 경계 `/api/tts-timing`, 화면 `charTimes`·`speakSegment`(문장 소리에서 단어 구간만 재생). 일본어 음성은 나나미·케이타 2종뿐.
- 측정 결과(2026-10-27, README 참고): 경계 시간은 실제 소리보다 시작 약 100~200ms 일찍, 끝 약 55~175ms 늦다. 한자 읽기는 二日·一人·大人는 맞고 市場는 「しじょう」로 읽어 틀리며 十分·日本人은 불분명.
