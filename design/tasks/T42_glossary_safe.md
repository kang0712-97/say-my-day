# T42 내 표현 사전: 문맥 우선 + 이름/표현 + 반영 표시
상태: 완료(미확인: 실제 AI 번역 품질 — API 크레딧이 없어 시험 못 함, 중국어 문구)
배경: 별명(가까운 사람 이름)을 사전에 두면 음식 우동 일기도 사람 이름으로 번역될 수 있다는 걱정(2026-11-02). 사전을 없애지 않고 안전하게 만든다.

## 한 일
1. **문맥 우선 규칙**(서버 `GLOSSARY_RULE`): 용어가 하나라도 붙을 때 프롬프트 끝에 "문맥이 그 뜻일 때만 적용, 같은 글자가 일반 단어(음식·물건·동물)로 쓰이면 일반 뜻, 애매하면 일반 뜻, '항상'이라고 적혀 있어도 이 규칙 우선, 원문에 없는 내용 금지"를 붙인다. `prompts/user_glossary.md`의 별명 항목에서 모순이던 "항상 사람 이름"를 지우고 "사람 문맥에서는 사람 이름, 먹다·맛·국물·면·주문 같은 음식 문맥이거나 애매하면 음식 이름"으로 고침.
2. **종류 고르기**: 설정의 "내 표현 사전"에 종류(이름/표현) 선택 추가. 이름은 서버가 "[이름] … 사람·동물 이름으로 쓰인 문맥에서만 적용, 일반 단어 문맥이면 일반 뜻"을 자동으로 덧붙인다. 입력 안내 문구도 종류에 따라 바뀜. 예전 항목은 "표현"으로 취급.
3. **반영 표시 + 다시 번역**: 번역 응답에 `glossaryUsed`(이번 일기에 들어 있는 용어: 파일 용어집 + 앱 용어)를 실어, 결과 화면 위에 "내 표현 사전 반영: (용어)" 과 [사전 없이 다시 번역] 버튼을 보임. 누르면 같은 일기를 용어 없이(파일 용어집도 제외) 다시 번역해 같은 일기 항목을 대체하고, 그 결과에는 "사전 없이 번역함" + [사전 넣어 다시 번역]이 나옴.
- ZH 문구 추가. 백업 `backup/server_용어규칙전_v10.js`(실제로는 server.js 복사), `index_용어사전전_v79.html`.

## 알려진 것
- 시험: 분리 서버(포트 3077)에서 `glossaryUsed`가 파일 용어집(별명 두 가지 표기)과 앱 용어를 맞게 돌려주는지, noGlossary 때 `glossarySkipped`가 true인지 확인. 화면에서 종류 선택·목록 표시·반영 표시 확인.
- 확인 못 한 것: 실제 AI가 "(별명) 먹었다/(별명)이랑 영화 봤다/(별명)이 맛있었다"를 맞게 옮기는지(크레딧 충전 뒤 확인 필요). 한 일기에 두 뜻이 섞이면 틀릴 수 있어 "사전 없이 다시 번역"이 안전망.
