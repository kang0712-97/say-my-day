# T44 학습 화면 재설계 제안 (이 앱의 핵심)
상태: 제안 — 사용자 결정 대기(2026-11-03). 코드는 바꾸지 않음.
그림: `design/T44_learning_flow.png`(세션 흐름), `design/T44_learning_cards_mock.png`(카드 샘플)
검토 방식: 현재 코드(결과 화면 구조·`learnHtml`·`openRead`·`speak-check`)와 `mock.json` 결과 구조를 읽고, 학습자·UX 두 관점으로 평가. 실제 사용자 관찰이나 사용 기록은 없음(한계 참고).

## 1. 결론
- 지금 문제는 "스크롤이 길다"가 아니라 **화면이 정보의 종류(문장·단어·문법·활용 문장)로 나뉘어 있고, 학습자가 하는 행동(보기·듣기·말하기·꺼내기)으로 나뉘어 있지 않다**는 것이다.
- 이 앱의 약속은 "내 하루를 외국어로 말할 수 있게"인데, 현재 구조는 **입력(읽기·듣기) 중심**이고 **꺼내서 말하기(인출)** 가 약하다.
- 제안: 번역이 끝나면 **"학습 세션"**(전체 화면 카드)으로 들어간다. **문장 하나를 끝까지** 다룬 뒤 다음 문장으로 가고, 마지막에 **가리고 말하기 → 이어 말하기 → 마무리**로 끝낸다. 지금의 긴 목록은 "전체 보기"로 남겨 참고용으로 쓴다.

## 2. 사용자(학습자) 관점
**누가·언제·왜**: 자기 일기를 쓴 직후라 내용이 자기 이야기라서 동기가 가장 높은 순간이다(자기 이야기는 더 오래 기억된다). 한 손으로 폰을 들고 3~7분 안에 끝내고 싶다. 목표는 "저 문장을 내 입으로 말해 보는 것"이다.

**지금 겪을 문제(코드·화면 근거)**
1. **문맥 단절**: 핵심 단어는 일기 전체에서 모아 따로 나열된다(예시 일기: 문장 4개, 단어 9개). 단어를 보다가 "어느 문장의 단어였지"를 잃는다.
2. **선택 과부하**: 한 문장 카드에 듣기·저장·복사·마이크·설명·단어 누르기·한국어 가리기, 화면 위에는 보기 방식·속도·병음 옵션까지 있다. 주 행동이 하나로 보이지 않는다(앞서 정한 "화면당 주 행동 1개"와도 어긋남).
3. **같은 일을 하는 입구가 여러 개**: 목록 보기 / 한 문장씩 / 일기 전체 읽기(따라 읽기 오버레이) / 퀴즈 / 마무리. 어디로 가야 하는지 학습자가 정해야 한다.
4. **꺼내기(인출)가 없다**: 보고 듣고 따라 읽기만 하면 "아는 느낌"만 생기고 기억은 약하다. 한국어만 보고 외국어를 말해 보는 단계가 없다.
5. **복습 재료가 안 쌓인다**: 단어장은 사용자가 별을 눌러야 저장된다. 대부분 누르지 않으므로 복습 알림도 비어 있게 된다.
6. **위치 감각이 없다**: 지금 몇 번째 문장인지, 앞으로 얼마나 남았는지 알기 어렵다. 중간에 나가면 자리가 사라진다.
7. **정보량**: 한자·병음·끊어 읽기·메모·발음 팁·단어·문법·활용 문장이 모두 한 번에 있다. 초급자에게는 많다.

## 3. UX 관점: 설계 원칙
1. **한 번에 하나**: 화면에 카드 한 장, 주 버튼 하나.
2. **문장이 중심**: 단어·문법은 그 문장에 붙여서 보여 준다.
3. **입력 → 이해 → 생산 → 인출** 순서(위 그림).
4. **끝낼 수 있는 크기**: 문장 3~5개, 6~8분 안팎. 시작할 때 "4문장, 새 단어 6개"를 알려 준다.
5. **점진적 공개**: 첫 화면은 문장과 소리만. 병음·뜻·메모는 한 번 더 눌러서.
6. **손실 없음**: ×로 나가도 자리를 저장하고, 이어서 열면 그 카드부터.
7. **압박 없음**: 말하기·가리고 말하기는 항상 건너뛸 수 있다. 틀려도 점수·벌칙 문구 없음.
8. **엄지 영역**: 주 버튼을 화면 아래, 높이 52px, 버튼 사이 8px 이상. 본문 18~20px, 병음 12~14px.
9. **구분은 세 가지 신호를 함께**(색에 기대지 않음): ① 위쪽 단계 표시 `① 문장 · ② 단어 1/3 · ③ 문법 · ④ 말하기` ② 카드 바탕(흰 종이 / 회색 종이 / 줄 노트) ③ 새 자세(듣기·읽기·생각·완료).
10. **접근성**: 카드 전환은 좌우 슬라이드(움직임 줄이기면 페이드), 읽는 순서는 카드 안 위에서 아래, 키보드·버튼으로도 이동 가능, 소리는 자동재생하지 않고 큰 ▶ 버튼(브라우저가 자동재생을 막음).

## 4. 제안하는 세션(그림 참고)
문장마다 반복: ① 듣고 보기 → ② 따라 말하기 → ③ 새 단어(0~3장) → ④ 문법(0~1장). 모든 문장이 끝나면 ⑤ 가리고 말하기(문장마다) → ⑥ 이어 말하기 → 마무리.

| 카드 | 보이는 것 | 주 버튼 | 건너뛰기 |
|---|---|---|---|
| ① 듣고 보기 | 내 한국어(작게) + 외국어 크게 + 끊어 읽기, 병음은 토글 | ▶ 듣기(다음은 아래 "다음") | 없음(이동만) |
| ② 따라 말하기 | 같은 문장 + 마이크 | 🎤 말하기 | 가능 |
| ③ 새 단어 | 이 문장에서 나온 단어 중 단어장에 없는 것만, 뜻·읽기·예문 1개 | 다음 단어 | 가능 |
| ④ 문법 | 이 문장에 쓰인 패턴 한 줄 + 바꿔 말하기 예문 1개 | 다음 | 가능 |
| ⑤ 가리고 말하기 | 한국어만. 힌트 3단계(첫 단어 → 병음 → 정답) | 🎤 / "기억났어요 · 한 번 더" | 가능 |
| ⑥ 이어 말하기 | 내 일기 전체 줄 목록, 말한 줄에 체크 | 🎤 | 가능 |
- **단어는 자동으로 단어장에 담긴다**("새 단어 6개를 담았어요", 빼기 가능). 이미 아는 단어는 카드에서 생략. 사용자가 수고하지 않아도 복습 재료가 쌓인다.
- **마이크가 안 되는 환경**(http 주소, 일부 브라우저)에서는 ②·⑥은 "소리 내어 말했어요" 버튼으로, ⑤는 "기억났어요 / 한 번 더" 두 버튼만으로 진행한다.
- ⑤의 "한 번 더"는 기존 복습(보관함) 일정에 반영해 다음에 다시 나오게 한다.

## 5. 대안 비교
| | A 문장 중심 루프(권장) | B 카테고리 중심(현재와 비슷) | C 하이브리드 |
|---|---|---|---|
| 흐름 | 문장 1 끝까지 → 문장 2 … | 문장 전부 → 단어 전부 → 문법 전부 | 문장 루프, 단어·문법은 "모아 보기" 선택 |
| 몰입 | 높음(문맥 유지) | 낮음 | 중간 |
| 구현 | 중간(문장별 매핑 필요) | 낮음 | 높음 |
| 위험 | 카드 수가 많아 길게 느껴질 수 있음 | 지금의 문제가 남음 | 선택이 늘어 복잡 |
A를 권장. B는 빠른 구현은 되지만 "몰입" 요구를 해결하지 못한다.

## 6. 구현 시 주의(개발 쪽 사실)
- **단어 매핑**: 문장 JSON에 `words`가 있고 `vocab`은 일기 전체 목록이다. `vocab.zh`가 문장 `zh`에 들어 있는지로 클라이언트에서 맞출 수 있다(번역 프롬프트 변경 불필요).
- **문법 매핑**: 문법 항목은 `pattern`·`example`만 있고 어느 문장에서 나왔는지 없다. 정확히 붙이려면 번역 프롬프트에 `sentence_n` 필드를 추가해야 한다. 크레딧이 충전돼야 품질 시험이 가능하다. **1단계는 문법을 마지막에 "오늘의 문법"으로 모아 보여 주고**, 필드가 안정되면 문장별로 옮긴다.
- **마이크**: 크롬 + https/localhost에서만 된다(`http://172.x` 휴대폰 확인에서는 막힘). 실제 폰 시험은 https 주소가 필요하다. 마이크가 안 되는 쪽 흐름을 처음부터 만든다.
- **재사용**: 따라 말하기 확인(`speak-check`), 단어·문법 렌더 부품, 밀어 넘기기(일기책 드래그), 마무리 화면은 그대로 쓴다. 새로 만드는 것은 카드 틀·진행 상태·자리 저장·인출 카드.
- **이전 결정과 충돌**: "접지 않고 모두 펼침"(T38 R3)은 긴 스크롤에서 길을 잃는 문제를 풀려던 결정이다. 카드 방식은 같은 문제를 다른 방법(한 번에 하나)으로 해결하므로 이 결정을 **카드 안에서의 점진적 공개로 바꾸는 것**이다. 문장별 설명 접기(T41)는 카드 안 "설명 보기"로 이어진다.
- **시험**: 현재 화면 구조(#sentences, #steps 등)를 가정한 화면 시험과 접근성 시험을 새 구조에 맞춰 고쳐야 한다.

## 7. 작업 순서
| 카드 | 내용 | 비고 |
|---|---|---|
| L1 | 세션 틀(전체 화면·진행 표시·이전/다음·밀기·자리 저장) + ① 듣고 보기 | "전체 보기"로 목록 유지 |
| L2 | ② 따라 말하기, ③ 새 단어(자동 담기·되돌리기), ④ 문법(모아 보기) | |
| L3 | ⑤ 가리고 말하기, ⑥ 이어 말하기, 마무리 연결 | |
| L4 | 새 자세 연동, 문구(한·중·일), 접근성·시험 정리 | |
| L5 | 문법 문장별 매핑(`sentence_n`) | 크레딧 충전 후 |

## 8. 확인 방법(만든 뒤)
- 3~5명에게 일기 하나를 쓰고 끝까지 학습하게 하고, 말없이 지켜본다: 어디서 멈췄나, 건너뛴 카드, 끝까지 간 시간.
- 기기 안에서만 세는 값(서버로 보내지 않음): 세션 완료 여부, 카드 수, 말하기 시도, 가리고 말하기 "한 번 더" 비율. 사용자에게는 "오늘의 나"로만 보여 준다.
- 기준: 세션 끝까지 가는 비율, 6~8분 안에 끝나는 비율, 다음 날 복습 시작 비율.

## 9. 한계
- 실제 학습자 관찰·사용 기록이 없어 시간(6~8분)·카드 수는 어림이다. 코드와 예시 결과(`mock.json`) 기준이다.
- 실제 AI 번역 결과의 단어·문법 개수가 일기마다 다르다(예시는 문장 4·단어 9·문법 3·활용 4). 많은 일기에서 카드 수가 늘 수 있어 "문장당 단어 최대 3장" 같은 상한이 필요하다.
- 휴대폰 마이크·소리 자동재생·밀기 느낌은 실기기에서 확인해야 한다.
