상태: 계획 제안(사용자 승인 대기, 2026-11-02)
근거: 2026-11-02 사용자 요구 12항목(아래 R1~R12). UX·개발·사용자 3관점 검토 후 작업 묶음 제안. T36(일기책)·T37(컨셉)을 흡수·수정한다.

## 0. 먼저 알아야 할 사실 (확인함)
- **"API 오류 400" 원인 = Anthropic API 크레딧 부족** ("Your credit balance is too low"). 코드 버그 아님. 글자 풀이(`/api/chars`)와 번역 모두 같은 키라 **지금 번역도 실패할 가능성이 높다**. 사용자가 Plans & Billing에서 충전해야 함(Render 환경변수의 키가 같은 계정인지도 확인). 앱 쪽 보완: 오류 문구를 "지금 풀이를 불러올 수 없어요. 잠시 후 다시" 로 바꾸고 다시 시도 버튼, 풀이 결과 캐시.
- "내 음성 녹음이 안 됨": 지금 있는 건 **음성 인식**(말한 글자 비교, 소리를 저장하지 않음)뿐이고 **녹음·재생은 없다**. 인식은 크롬·https/localhost에서만 되고 `http://172.x` 같은 LAN 주소에서는 마이크가 막힌다. (디자인 스킬의 "녹음·음성 채점 금지"는 이번 요청으로 사용자가 뒤집는다 → 기록)
- 사용자 요구가 이전 결정과 충돌하는 곳: ① T29b(접는 아코디언)→ **고정 펼침**으로 번복 ② T36의 "내 일기책" 별도 진입 → **일기장 안으로 통합** ③ 속도·간격 칩 중 간격 칩 제거 ④ T33b 새 성장 "보류" → **새 키우기가 핵심 동기가 되어 최소판 필요**(꾸미기는 계속 보류).

## 2. 추가 의견 (사용자가 말하지 않았지만 필요하다고 보는 것)
1. **한 줄 여정 정의**: 펼침(홈) → 쓰기 → 번역 중(새) → ①한 문장씩 → ②전체 읽기 → ③마무리(새 칭찬) → 홈. 단계 표시줄을 번역 화면 위에 고정해 지금 어디인지 보이게.
2. 접기를 없애면 문장 카드가 길어진다 → 단어·문법·예문은 문장 카드 **안에 문장별로** 두고(그 문장 것만), 전체 문법 모음은 마지막 "정리" 구역으로. 길이 상한(단어 최대 8개 등)을 프롬프트/화면에서 관리.
3. 새 한마디 문구를 앱 전체 하나의 목록(`bird-lines.md`)으로 확장, 화면별 맥락(홈/번역중/마무리/주간) 키로 관리. 중국어·일본어 번역 필수(`T`/`L()`).
4. 발표용 데모 데이터: 일기 3~5편이 들어 있는 시험용 샘플을 한 번에 불러오는 방법(데이터 안전 규칙: 실제 데이터에는 쓰지 않음, 분리 서버).
5. 접근성: 책 넘기기는 스와이프 외에 버튼·키보드 대체 유지, 움직임 줄이기 시 페이드. 색이 아닌 모양으로 쓴 날 표시(깃털).
6. 유료 서비스 금지 결정과 API 크레딧: 번역은 어쩔 수 없이 유료 API. **크레딧 소진 대비**: 번역 결과 캐시·남은 예산 점검·발표 전 충전 확인.

## 4. 결정할 것 (사용자)
1. 발표 날짜(남은 일수)와 데모에서 꼭 보여 줄 장면: 어디까지를 발표 전에 끝낼지 정한다.
2. API 크레딧 충전 가능 여부(발표 전까지).
3. 일기책 쪽 구조에서 "한 문장씩 펼치기"는 쪽 안에서 문장 카드가 펼쳐지는 방식(추천)으로 할지, 쪽을 한 번 더 넘기는 방식으로 할지.
4. 녹음은 "기기 안에서 바로 다시 듣기"(추천, 저장 안 함)로 시작해도 되는지.
5. 새 키우기 최소판(단계·학습 일수·깃털 적립)을 T38d·h에서 시작하고 꾸미기만 보류해도 되는지.
