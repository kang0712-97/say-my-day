# T20 읽기 표시 구조: ruby
상태: 대기
근거: `design/redesign-plan.md`(읽고 시작), `/say-my-day-design` 스킬 절차, DESIGN.md '서체와 읽기', tokens.json reading, `design/tasks/T1`·`T7`·`T8` 카드

## 할 일
1. **먼저 결정(작은 시험 코드로):** A) 단어 단위 `<ruby><rb><rt>` 완전 전환, B) 현재 한 글자 한 칸(`.c`) 구조를 유지하고 ruby 의미를 보강. 기준: 따라 읽기 형광펜(`charTimes`)·단어 누르기(`.wd`)·문장 속 위치(`ctx_i`)·확인 표시(`.chk`)·문장부호 묶음(`.nw`)이 깨지지 않을 것, 200% 확대에서 겹침 0, 단어+읽기가 함께 줄바꿈. 결정과 이유를 카드 결과에 적는다.
2. 선택안 구현: 병음/후리가나 12/18, 글자 26/46(학습 대상), 기본 병음은 사전형 성조(성조 변화는 발음 팁에서만).
3. 일본어 다글자 읽기(`.rg`)·애매한 읽기 `확인` 표시(텍스트+아이콘)·글자 풀이 호출 유지.

## 반드시 유지할 기능 (기능 확인표 번호는 계획서 §4)
F3 읽기 전부, F5 글자 강조, F2 글꼴 전환. `tokens.json`의 reading 규칙.

## 완료 기준
- 고정 샘플 3조합에서 읽기가 글자 위에 정렬, 360px·200%에서 겹침 0, 줄바꿈 때 단어와 읽기가 함께 이동.
- 단어 누르기·미니 카드·따라 읽기 형광펜 동작(스모크+`tests/char_times_check.js`).
- 복사한 텍스트에 병음이 섞이지 않음(`copyBtn`).
- `pinyin_check`, `pinyin_context_check`, `ja/missing_reading_check` 통과.

## 검증 방법
`npm test` 통과(분리 서버), 라이트·다크 × ko>zh·ko>ja·zh>ja × 폭 360/390 스크린샷을 해당 보드와 나란히 비교, 글자 200% 가로 넘침 0, 사용한 색 쌍을 `contrast-check`로 재계산. 소리·실기기는 "미확인"으로 적고 사용자에게 요청.
추가: 스크린 리더로 한자 위 읽기가 어떻게 읽히는지 샘플 3화면은 사용자 확인(미확인 가능). 일본어는 '市場' 같은 애매한 읽기 표시를 스크린샷으로 확인.
