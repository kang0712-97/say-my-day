# T18 접근성 점검 + 기기 매트릭스
상태: 완료(기기 표는 사용자 몫)
근거: `hardening-plan.md §5 T18` (읽고 시작)

## 할 일
이름 없는 버튼·`lang` 속성·포커스 순서 자동 검사, `contrast-check`로 라이트/다크 색 대비, 글자 200% 넘침. 기기 매트릭스 표는 사용자가 실기기(폭 320/360/390/430, 안드로이드·아이폰)로 확인.

## 완료 기준
- 자동 검사 0건, 기기 표의 × 항목 이슈화.

## 결과
**완료.** `tests/a11y/`(`npm test`에 포함)가 3개 조합×쓰기·언어 고르기·결과·단어 카드/페이지·통독·퀴즈·시트를 훑어 이름 없는 버튼·링크·입력, img 대체 텍스트, `tabindex>0`, 눌리는 곳 24px 미만, 한자·가나·한글 조각의 `lang`, 결과 문장 안 포커스 순서, 글자 200%(360px 폭) 가로 넘침을 검사한다. 처음 546건 → 고친 뒤 0건.
고친 것: ① 일본어 읽기(`.py`)·문형(`.pat`)에 목표 언어 `lang` 추가(스크린 리더가 한국어 음성으로 읽던 문제) ② 단어 버튼 최소 폭 24px ③ 글자 200%에서 긴 단어·인트로 제목이 화면 밖으로 나가던 것(`.wd` 줄바꿈 허용, `.circled`의 `nowrap` 제거, 히어로 글 칸 `min-width:0`). 백업 `backup/index_접근성전_v32.html`.
색 대비: `contrast-check`로 라이트·다크 글자/배경 짝 전부 본문 4.5:1 이상 통과(가장 낮음 라이트 muted on desk 4.69, 나머지 5 이상).
**미확인:** 스크린 리더로 직접 듣기(한자 위 병음 이중 줄), 기기 매트릭스 — `design/device-matrix.md` 표를 사용자가 실기기로 채우면 ×를 이슈화. 한계: 포커스 순서는 DOM 순서와 화면 위치만 비교(실제 Tab 키 시험 아님), 고정 샘플의 한국어 원문은 zh UI에서 한글 lang 검사 제외.
