# say-my-day-design — 그림일기 디자인 적용 절차

기준 폴더: `design-system-final-2026-10-29/` (프로젝트 루트). 원본이 항상 우선이며 이 스킬에 값을 옮겨 적지 않는다.

## 1. 읽을 것 (필요한 만큼만)
1. `design/tasks/README.md` 현황판 → 해당 카드 한 장(`T19`~`T28`). 계획 전체는 `design/redesign-plan.md`(기존→새 화면 대응, 기능 확인표, 충돌 정리).
2. `design-system-final-2026-10-29/DESIGN.md` — 해당 화면의 "기능별 화면"·"컴포넌트와 상태"·"작은 새 캐릭터의 고정 규칙"만.
3. 값(색·크기·간격·반경)은 `tokens.json`/`tokens.css`에서 읽는다. 코드에 새 숫자를 만들지 않고 CSS 변수로 쓴다.
4. 시각 확인은 `boards/` 4장 중 해당 화면. 보드의 작은 문구·생성 글자는 오류가 있을 수 있으니 **문구는 앱의 기존 한국어/`ZH` 사전**을 쓴다.
5. 새 이미지는 `assets/` 12종 중 `redesign-plan.md`의 "상태→이미지" 표대로만 쓴다.

## 2. 적용 규칙 (원본과 다를 때 원본이 이긴다)
- 이전 "차분한 저널"(크림·세리프·붉은 포인트, `design/directions.html`, 스킨 시험 `design/skin-test.md`)은 폐기. 충돌하면 새 기준.
- **기능은 시안에 없어도 유지**한다: 지원 언어쌍 3개, 입력 언어 = UI 언어, 읽기 표시, 음성·글자 강조, 퀴즈·복습 일정, 저장·백업. 체크는 `redesign-plan.md`의 기능 확인표.
- 캐릭터: 쓰는 장면(`02-writing`)만 펜을 날개로 잡는다. 나머지는 모두 머리 옆 깃털에 펜을 꽂은 자산을 쓴다. 이미지를 자르거나 뒤집거나 색 반전하거나 두 마리를 만들지 않는다. 상태 안내는 항상 글자+아이콘을 함께(캐릭터만으로 알리지 않는다).
- 색은 흑백이 기본. 확인 필요(호박)·삭제(붉은)만 의미색. 상태는 색만으로 구분하지 않는다(아이콘·문구·모양 병행).
- 최소 조작 44px, 주요 버튼 56px 캡슐, 포커스 2px 외곽선+2px 간격, 움직임 줄이기 존중.
- 읽기 표시는 글자 위 ruby, 단어 단위 줄바꿈 유지. 따라 읽기·형광펜이 기대는 기존 구조(`.c` 한 글자 한 칸, `ctx_i`, `charTimes`)를 깨기 전에 카드 T20의 결론을 따른다.
- 요소 `id`·`data-*`·함수 이름은 가급적 유지한다(시험 도구 `tests/smoke`·`tests/a11y`가 기대는 것). 바꾸면 같은 카드에서 시험도 고친다.
- 새 문구는 `L()`/`ZH` 사전에 중국어까지 추가하고 `node tests/i18n_keys_check.js`로 확인한다.

## 3. 검증 (카드 완료 전 순서대로)
1. `node --check`(스크립트 블록), `npm test`(순수 검사+스모크+접근성) — 분리 서버만 사용.
2. 해당 화면을 크롬으로 열어 **ko>zh, ko>ja, zh>ja × 라이트/다크 × 폭 360/390/768** 스크린샷으로 보드와 비교(`tests/browser_check.js`, `PRESET`·`SHOT`).
3. 글자 200%에서 가로 넘침 없음, 이름 없는 버튼 없음, 색 대비는 `contrast-check` 스킬로 사용한 색 쌍을 다시 계산.
4. 카드 `완료 기준`의 기능 항목을 직접 눌러 확인(소리·휴대폰은 "미확인"으로 적고 사용자에게 요청).
5. 끝나면 카드 결과·현황판·`README.md` 한 줄·로컬 커밋. push는 사용자 승인 후에만.

## 4. 하지 않는 것
유료 서비스, 녹음·음성 채점, 소셜·경쟁 요소, AI가 만든 기분 이미지, 연속 기록을 압박하는 문구, 캐릭터 애니메이션 기본값.
