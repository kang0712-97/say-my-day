# 프롬프트.md — Say My Day (PO 직군)
AI(Claude Code·Claude API)를 어떻게 썼는지 기록한 문서입니다. 파일 위치는 저장소 기준입니다.

## 1. 앱 안에서 쓰는 프롬프트: 번역·해설 시스템 프롬프트 v0.1 → v0.5
파일: `prompts/system_prompt_v0.1.md` … `v0.4.md`, 현재본 `prompts/system_prompt.md`(v0.5). 각 파일 머리글에 "이전 버전 대비 변경"이 적혀 있습니다.

| 버전 | 바꾼 것(파일 머리글 인용) | 왜 바꿨나 |
|---|---|---|
| v0.1 | 0단계 검증용. HSK 1~3급, 자연스러운 번역, 병음은 앱이 생성, 모호한 말은 `ambiguities`, 일기에 없는 사실 금지, JSON만 출력 | 키 없이 Claude Code 세션이 규칙대로 직접 만든 시뮬레이션 결과(`tests/sample_01.md`)로 규칙이 통하는지 먼저 확인 |
| v0.2 | 긴 문장 분할(`zh_split`), HSK 급수 필드 삭제, 단어 선택 이유 `note` 의무화, 사용자 용어집 주입, 말장난·오타 처리 규칙 | 문장이 길면 소리 내어 읽기 어렵고, 번역이 왜 그렇게 됐는지 학습자가 알아야 해서 |
| v0.3 | 단어·문법·활용 문장 예문마다 한국어 뜻(`example_ko`, `ko`) 추가 | 예문만 있으면 학습자가 뜻을 확인할 수 없어서 |
| v0.4 | **독립 감수 반영**: 입력을 번호 붙은 문장 목록으로, 원문 `ko`는 앱이 보존, HSK 3급 규칙 강화, 어감 변화 `note` 의무화, 단어·문법 선택 기준 규칙화, 발음 팁 중복·부정확한 한국어 소리 비유 금지, 혼용 표기 처리 | 아래 §2의 독립 감수에서 나온 문제 6가지 |
| v0.5 | 문장마다 단어 단위 분해(`words`), `ambiguities`를 문장 번호가 붙은 객체로, `vocab`을 중요한 순서로 정렬 | 앱에서 단어를 눌러 뜻·발음을 보고, 문장 옆에 "확인 필요"를 붙이려면 구조가 필요해서 |

**번역 품질을 높이려고 프롬프트 밖에서 보완한 것(AI 출력을 그대로 믿지 않는 장치)**
- 병음은 AI가 만들지 않고 앱이 `pinyin-pro`로 만든 뒤 `app/public/pinyin-fix.js`의 교정 표(경성·得 등)로 보정 → `tests/pinyin_check.js`, `pinyin_context_check.js`가 지킴
- 원문 `ko`는 AI가 바꿀 수 있어 앱이 보존(`자격증→자격证` 사고 이후)
- 문장 나누기·읽기 누락은 코드 검사(`split_check.js`, `ja/missing_reading_check.js`)
- **표현 사전(용어집) 문맥 우선 규칙**(`app/server.js`의 `GLOSSARY_RULE`): 이름과 일반 단어가 같을 때(예: 별명이 음식 이름과 같은 경우) 문맥이 그 뜻일 때만 적용, 애매하면 일반 뜻. 이름/표현 종류 선택, "내 표현 사전 반영" 표시와 "사전 없이 다시 번역"

## 2. 독립 감수(AI가 쓴 결과를 다른 AI 관점으로 검토)
기록: `tests/review_01.md`(2026-10-14). 감수자는 파일을 읽기만 했고 프롬프트 v0.3 + 화면 v1 + 실제 응답 `tests/real_01.json`을 검토했습니다. 지적과 조치:
1. 원문이 바뀌어 표시(`자격증→자격证`) → 원문은 앱이 보존(v0.4)
2. `沉浸`, `编程` 등 3급 초과인데 note는 "쉽게 썼다"고 해 모순 → 3급 규칙 강화, 어감 note 의무화
3. 호감의 어감이 약해짐, `幸福` 어감 note 없음 → 어감 변화 note 의무화
4. 단어 선택이 너무 쉬운 말 위주, 핵심어 누락 → 단어 선택 기준 규칙화
5. 발음 팁 중복, ㅅ·ㅎ 혼합 비유 → 중복 금지, 부정확한 소리 비유 금지
6. 병음 라이브러리의 경성·得 오류 → 교정 표 + 시험

## 3. 개발에 쓴 지시 방식
**작업 카드 한 장 = 새 대화 하나.** `design/tasks/T*.md`(66장)와 현황판 `design/tasks/README.md`로 한 번에 한 기능만 진행하고, 카드마다 "완료 기준 → 시험 → 기록 → 로컬 커밋"을 지켰습니다. 사용자 요구는 AI가 3관점(UX·개발·학습자)으로 검토해 제안하고, 사용자가 승인하면 실행하는 순서였습니다(`design/tasks/T38_journey_redesign_plan.md`, `T44_learning_flow_proposal.md`).

실제 사용한 지시 발췌(개인 이름은 일반 표현으로 바꿈):
- 작업 시작: "프로젝트 폴더의 CLAUDE.md와 `design/tasks/README.md`를 읽고, 현황판에서 [카드]를 진행해줘. 계획은 [계획서]의 해당 부분을 보고, 새 그림은 기존 것을 쓰되 나중에 교체하기 쉽게 하고, 완료 기준에 '일기장 컨셉 점검표'를 넣어줘."
- 디자인 방향: "확인 완료. 근데 아직 일기장 같은 느낌은 아니야. 첨부 이미지처럼 진짜 일기장 같으면 좋겠어." → AI가 범위·쓰기 칸 모양을 선택지로 되물음 → 그림일기 한 장 양식
- 핵심 설계 검토: "사용자 입장과 UIUX전문가의 입장에서 이 학습 부분 설계를 심도있게 검토해서 제안해줘. 이게 이 앱의 핵심이야." → 문제 7가지 진단 + 문장 중심 카드 세션 제안서(`T44`)
- 설계 단순화: "지금 번역해서 진행하는 구성이 너무 복잡해. 문장 하나씩 들으면서 말해보고, 단어 리스트 외우고, … 전체 읽어보기로 끝내자. 단어는 많은데 리스트에 나오는 단어가 너무 적은 것 같아." → 카드 수 축소, 단어 리스트를 9개에서 24개로(같은 입력 기준)
- 세부 위계: "이전과 다음 버튼 길이가 같아야지, 둘 다 글씨에 비해 버튼이 커." → 폭 1:1, 높이 48px, 글자에 맞춰 줄임
- 도메인 문제를 AI와 함께 고민: "가까운 사람의 별명이 음식 이름과 같을 때, 음식 일기도 사람 이름으로 번역될 텐데 어떻게 해결할 수 있을까? 설정 자체를 없앨까?" → 없애지 않고 3중 안전장치(문맥 우선 규칙·이름/표현 종류·반영 표시와 되돌리기)
- 버그 신고: "일기장에서 일기 목록 삭제하려는데 삭제가 안 돼." → 원인 추적·재현·수정·시험 추가(§4 ④)

## 4. CLAUDE.md와 스킬
- `CLAUDE.md`(저장소 루트)의 핵심 규칙: ① 사용자에게 한국어로, 결론부터 짧게 ② 작업 카드 방식 ③ **데이터 안전**: 시험은 항상 분리한 서버·임시 프로필로, 실제 `data/`는 건드리지 않음 ④ API 키는 출력·커밋 금지, 커밋 전 키 검사 ⑤ **push는 사용자 승인 뒤에만** ⑥ 큰 수정 전 `backup/`에 이전 버전 보관, 작업 끝에 진행 기록과 로컬 커밋
- 스킬: `/say-my-day-design`(확정 디자인 시스템 기준 절차, 카드 T19~T28에서 사용), `contrast-check`(라이트·다크 색 대비 4.5:1 검사, 카드 T18), 그 밖에 프로젝트 안에서 `archify`·`commit-msg`·`api-check` 스킬을 설치해 두었으나 위 두 가지만 카드 기록에 근거가 남아 있음
- 사용자 선호는 대화 기억으로 저장해 이어 감(예: 토큰 절약, 한 번에 한 가지, 압박·해명 멘트 금지, 이모지 금지)

## 5. AI 실수와 고친 과정 (실제 있었던 일)
| # | 무슨 일 | 어떻게 발견했나 | 고친 것 |
|---|---|---|---|
| ① | 표현 사전 항목 하나가 서로 모순("중국어로는 항상 A로" vs "음식 문맥에서는 B로") | 사용자가 "음식 이야기도 사람 이름으로 번역될 것 같다"고 문제 제기 → 코드·프롬프트 읽어 모순 확인 | "항상" 삭제, 문맥 우선 규칙을 서버에 고정, 이름/표현 종류, 반영 표시·되돌리기 |
| ② | 자동 시험이 실제 API 키를 읽어 시험마다 유료 호출(단어 설명) | 사용자가 "API가 벌써 다 떨어졌어?" 물음 → 시험 서버가 `.env.local`을 읽는 것 확인 | 시험 서버에 키를 빈 값으로 덮어써 호출 0회로, 시험 규칙을 기억에 저장 |
| ③ | 화면 시험용 가짜 학습일 23개가 실제 동기화 파일에 섞여 새 단계가 잘못 올라감 | 화면 캡처에서 새 단계가 이상해 확인 | 가짜 항목만 지우고(정리 전 파일 보관), 날짜 형식이 아닌 항목을 거르는 코드와 시험 규칙 추가 |
| ④ | 일기 삭제 확인이 바로 닫혀 삭제가 안 됨(수 주 전 카드에서 잠복) | 사용자 신고 → 브라우저에서 재현 → "바깥 클릭" 처리가 다시 그려진 단추를 바깥으로 오인 | 연결된 요소만 바깥 클릭으로 취급, 삭제 시험 추가 |
| ⑤ | 학습 흐름 제안에서 "따라 말하기(마이크)가 꺼져 있다"는 사실을 놓침 | 구현 중 코드에서 발견 | 마이크 없이도 되는 "소리 내어 말했어요" 흐름으로 먼저 구현, 사용자에게 사실 보고 |
| ⑥ | 디자인 제작 파일(171MB 압축 파일 등)이 커밋에 섞여 푸시가 거부될 뻔함 | 배포 직전 푸시 크기 점검 | 별도 복사본에서 기록을 정리해 푸시, 원본은 보존, 해당 폴더는 git 제외 |
| ⑦ | 번역에서 원문 낱말을 바꿔 적음(`자격증→자격证`) | 독립 감수 | 원문은 앱이 보존 |
| ⑧ | 화면 시험이 애니메이션 도중에 길이를 재서 오탐 | 접근성 시험 실패 로그 | 움직임이 끝난 뒤에 재도록 시험 수정 |
