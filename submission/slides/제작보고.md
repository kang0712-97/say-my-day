# Say My Day 발표 자료 제작 보고

- 완성 파일: 발표.html
- 구성: 16:9 본문 16장 + 부록 1장. 사용자가 확인한 개요 v2 순서와 장 제목을 모두 반영했습니다.
- 외부 라이브러리·폰트·스타일·스크립트 다운로드 없이 작동합니다. 이미지와 영상은 옆 폴더의 로컬 파일을 참조합니다.
- 수정·추가한 파일은 submission/slides/ 안에만 있습니다.
- 프롬프트 변경 기록과 AI 실수 표는 원문 내용을 옮겼습니다. 먼저 쉬운 말로 설계 판단을 보여 주고, 버튼을 누르면 기록 표가 펼쳐집니다.
- 후속 요청에 따라 대표 사용 장면과 PO의 설계 해석을 보강했습니다. 실제 측정값이나 개발 사건을 만들어 넣지는 않았습니다.

## 발표 조작

- ← / →: 이전·다음. 조각 공개 장에서는 강조할 항목을 먼저 옮깁니다.
- 화면 빈 곳 클릭 / Space: 다음 진행
- Home / End: 첫 장·부록
- N: 각 장의 발표 대본 3줄 표시·숨김
- G: 전체 목차
- F: 전체 화면
- 탭·뒤집기·펼침 버튼: 장 안의 상세 내용 변경
- 이미지 클릭: 원본 전체 확대. 세로 이미지는 아래로 스크롤해 읽을 수 있습니다.
- 브라우저 인쇄: 슬라이드마다 한 쪽. 선택한 탭·사례가 인쇄됩니다.

## PO 중심 구성

- 문제: 내 일기에서 얻은 번역문을 스스로 말하는 학습으로 잇기
- 우선순위: 쓰기에서 학습 마무리까지 핵심 흐름을 먼저 완성
- 범위: 마이크·정밀 평가·꾸미기·결제·가리고 말하기의 선택과 보류
- 판단: 집중을 위해 카드를 선택하며 조작 증가를 감수한 점
- AI 활용: 프롬프트 변경의 이유, CLAUDE.md와 스킬의 경계, 실제 실수의 발견·수정
- 회고: 화면 지표의 한계와 실제 학습자를 통한 다음 확인

## 사용한 수치와 출처

모든 비교 통계는 submission/metrics.json의 compare 항목에서만 가져왔습니다.

| 표시 수치 | metrics.json 경로 / 계산 |
|---|---|
| 25.9 → 13.2개 | compare.visibleChoices.before_avg_of_4 / compare.visibleChoices.after_avg_of_4 |
| 38% → 100% (mock.json 예시 한 건) | compare.wordCoverage.before["mock.json"] * 100 / compare.wordCoverage.after["mock.json"] * 100 |
| 9.3 → 13회 | mean(compare.stepsToFinish.before_swipes) = 9.25, 소수 첫째 자리 half-up 반올림 / mean(compare.stepsToFinish.after_taps) = 13 |
| 7.6~11 → 1.7~6.2화면 | min/max(compare.longestUnit.before_whole_page) / min/max(compare.longestUnit.after_tallest_card) |
| 단어 48개 | compare.wordCoverage.words_in_list.after[1] |
| 비교 입력 4건 | len(compare.visibleChoices.per_input.before) = 4 / len(compare.visibleChoices.per_input.after) = 4 |

- 단어 포함 38% → 100%는 mock.json 예시 한 건입니다. 모든 사례의 평균으로 표현하지 않았습니다.
- 조작 횟수는 이전 스와이프와 현재 탭을 비교합니다. 평균 9.25는 일반 반올림해 9.3으로 표시했습니다.
- 가장 긴 단위의 막대 길이는 각 범위의 최댓값을 쓰고, 값 라벨에는 전체 범위를 표시합니다.
- 사용자 완주율·학습 시간·만족도·번역 정확도는 측정 전입니다.
- 프롬프트 버전, 원문 표의 조건·사건에 포함된 숫자는 비교 통계가 아니므로 원문 그대로 보존했습니다.
- 작업 카드·커밋 집계는 compare 밖이므로 표시하지 않았습니다.
- HTML 맨 끝 주석에도 수치 경로와 계산 방법이 있습니다.

## 자료 부족·구현상 선택

- 발표자 이름만 미기재입니다. 개요에서 빠진 장은 없습니다.
- B안 디자인 개편의 구체적 이유는 원기록이 부족해 “PO의 해석”으로 보강했습니다.
- 16:9 한 장에 세로 휴대폰 캡처의 전체를 보존하면 실제 이미지 폭은 요청한 30~40%보다 작아집니다. 미디어 열과 비교 열은 약 34%로 배치하고 원본 전체 보기 및 클릭 확대를 제공합니다.
- 전후 비교 슬라이더는 이미지 일부를 가리지 않도록 두 전체 이미지의 비교 비중을 조절합니다.
